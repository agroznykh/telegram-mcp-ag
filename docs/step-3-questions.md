# Шаг 3 (кнопки): вопросы по ходу и принятые решения

Ты просил: на каждый вопрос предложить варианты, выбрать один и применить. Вот они.

## Вопросы при реализации

**1. Что значит `has_callback` для game-кнопки?**
- A. Оставить «только callback» (как сейчас), game нажимается, но флаг false — описать в docstring. **← выбрано.**
- B. Сделать true и для game.
- Почему A: в плане `has_callback` — «true только для callback без пароля (как сейчас)». Совместимость
  важнее; ассистент ориентируется на `kind`.

**2. Что показывать в `query` / `copy_text`, если они пустые?**
- A. Пустую строку. **← выбрано.**
- B. `[empty]` (так отвечает `sanitize_user_content`).
- Почему A: `[empty]` ассистент примет за настоящий текст кнопки (нашло ревью).

**3. Чистить ли URL?**
- A. Чистить и резать до 2048 везде (список, отказ, `url` ответа бота). **← выбрано.**
- B. Отдавать как есть, как апстрим.
- Почему A: URL пишет бот, это недоверенный текст; лимит 2048 не ломает обычные ссылки.

**4. Какой текст кнопки принимать при нажатии?**
- A. Как пришёл и как его показывает список (очищенный, обрезанный). **← выбрано.**
- B. Только как пришёл.
- Почему A: ассистент берёт текст из списка; с невидимыми символами и длинными подписями
  точное сравнение давало бесконечное «Button not found».

**5. Нумерация строк при пустой строке клавиатуры.**
- A. Пустая строка номера не занимает. **← выбрано.**
- B. Занимает (как в апстриме).
- Почему A: так же ведут себя пустые строки rich-блоков, нумерация одинаковая.

## Ревью безопасности

Находок нет. Нажатие по-прежнему шлёт только `getBotCallbackAnswer` (callback или game): пароль 2FA,
телефон, геолокация и текст reply-кнопок не отправляются ни при каких данных от бота.
